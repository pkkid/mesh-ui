## 5. Decisions made

Each can be reversed by number.

1. A write's gate is a field on its spec; `{ area: null }` means nothing
   limits it (#170).
2. An area eero does not send takes `network`'s update permission; a key it
   does not send takes its nearest sent parent; nothing covering it means
   eero decides (#180).
3. "Owner only" refuses only a known non-owner, so a failed permissions
   read never locks the owner out (#180).
4. `settings.impact` reads one `IMPACT` table; it does not know whether this
   computer is behind the network (#170).
5. A settings write that changes nothing is not sent; PPPoE always sends
   (#175).
6. PPPoE credentials go in `PUT {net}/settings`, not the encrypted
   `POST {eero}/pppoe` blob (#175, manual check).
7. Each Advanced networking change confirms and applies on its own; no
   batch "Apply" bar (#175).
8. Power schedule ids are `settings.power_schedule.*` (the registry allows
   three parts) (#182).
9. Simple Setup sends `LTS` for on and `OFF` for off, from one client
   (#182, manual check).
10. Thread Copy puts the credentials on the clipboard as lines, since eero
    sends no dataset (#182).
11. Integrations refuse unavailable or unlinked cases with eero's reason
    before sending (#171).
12. Routing writes all use the `settings` update gate, so admins can add and
    remove (#173).
13. `reservation.remove` keeps forwards unless asked; `forward.add` reserves
    the device's address first when it has none (#173).
14. `admin.nickname.set` is dropped; invites are QR or Copy link, never
    `mailto:` (#176).
15. Resend and New code cancel the old invite first; pending invites count
    toward the 10 seats (#176).
16. The gateway refusal for `eero.remove` is `bad_params` before the confirm
    (#172).
17. Long-running reads (diagnose, placement) poll every 3 s, bypass the 5 s
    read sharing and give up after 2 minutes (#174).
18. `coverage.scan` and `coverage.upgrade_report` are queries; placement
    and diagnose are writes without confirm (#174).
19. Notification settings have no gate; core sends the whole merged map
    (#177).
20. Activity rows link by unambiguous name only; the button shows only
    while the target still needs it (#178).
21. Palette Undo pairs come from the command id, only between two plain
    writes, pinned to the network on screen (#181).
22. Unassigned schedules use the `unassigned` ref on the existing profile
    commands rather than new ids (#184).

## 6. Numbers, surprises, open items, next

**Numbers.** 23 PRs, 842 to 1094 tests, `pnpm check` 5.2 s, 49 new
commands. Up to seven workers at once. Every PR but one got an outside
review (gpt-6.1-sol); it found real bugs in eight of them.

**Surprises.**
- The demo and fake permission shapes did not match eero's: the real role
  is `network-owner` and there are no `devices`, `profiles`, `settings` or
  `updates` areas. Every gated write would have been dimmed for the real
  owner. M5.4's capture caught it mid-run (#180, #183).
- The M4 manual checks were never run, so M5.1 had nothing to apply
  (question 1).
- The maintainer's manual checks found 13 real-network bugs that every
  sandbox test passed: wrong values or request bodies copied from
  untested open-source clients (Simple Setup, Thread off, schedule days),
  response shapes guessed rather than captured (coverage scan, upgrade
  report, profile members), a 403 read as a role problem when the hardware
  was the cause, and lists that were never polled. Fixed in #187 to #192.
  Lesson: a write proven only against our own fake is unproven; prefer a
  client that tested live (Eeronaut did, for each of these).
- One worker merged one commit behind `milestone/M5` (GitHub still said
  mergeable); one ended its run while its review was still running; one ran
  a bare `git stash` and restored it by SHA.
- Three stories edited files outside their list instead of stopping with
  needs-file (all small, unclaimed, accepted).

**Open items (carried in the roadmap under M6).**
- The Activity overflow menu and settings icon (question 3).
- Wi-Fi network nickname edit and Wi-Fi "Print a card" are still Coming
  soon (no command yet).
- Unrun disruptive manual checks (question 2).
- The fake admins list role (`owner`) and the real `{net}/admins` shape are
  unverified.

**Process lessons** (question 4):
- Worker prompt: before merging, check `git merge-base --is-ancestor
  origin/milestone/M<n> HEAD`; GitHub's mergeable flag is not enough.
- Worker prompt: never use bare `git stash` in a shared repo; use a WIP
  commit.
- `milestone-plan`: the first story's captures should check the permission
  and role shapes against every gate the fixtures assume; fixtures copied
  from docs hid a real-network break for a whole wave.
- `milestone-review`: grep the renderer for "Coming soon" when a Done when
  says none remain; it found three left (#185).
- Lead: after a review, confirm its manual checks are actually ticked before
  the next milestone relies on their answers.
