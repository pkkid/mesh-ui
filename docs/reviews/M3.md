## 1. Questions

All three answered by the maintainer on 2026-11-13.

1. **eero Simple Setup shows "unknown"** on Advanced networking: the real
   `auto_setup_mode` value is not an on or off word the mapper knows (#106).
   **Answer:** in M5, an agent prints only that one enum value with a
   read-only call and maps it. It stays "unknown" until then (carried to M5).
2. **Profiles shows "Today's pauses" lanes** (one lane per profile, as in
   mockup 07), not the roadmap's week overview, because one week grid would
   overlap several profiles (#102). The week timeline is used on profile
   detail and power saving.
   **Answer:** keep the lanes.
3. **Guest reads its password on page open** so the QR shows as in mockup
   11; Wi-Fi reads its password only on Show code or Reveal (#99, #104).
   Neither is polled or cached.
   **Answer:** keep guest auto-show.

## 5. Decisions made

Each can be reversed by number.

1. eero's Unassigned group is a profile with `default: true`; `profile.list`
   drops it, and any profile id not in `profile.list` counts as Unassigned in
   devices, usage and counts (#102, #108, #116).
2. Schedules come only from the profile's own `schedule[]`;
   `{profile}/schedules` is 404 (#98, #102).
3. Profile state and next change are computed in core in the network time
   zone (#102).
4. Notifications: eero sends only a network-wide `has_unread`, so real rows
   show as read and the bell dot follows the flag; Activity shows one
   "Unread" marker (#100, #113).
5. A new notification is an id this window has not seen; nothing alerts on
   first load; at most 5 alerts per poll; an eero alert opens the eeros page
   (eero links notifications only to devices) (#100).
6. Real events carry no device, eero or profile links, so those Activity
   filters match the event text, and row actions link to pages instead (#103).
7. "Per hour" on Activity covers the last 24 hours; "vs prior week" is left
   out when history is shorter (free accounts keep about 7 days) (#103).
8. Passwords and Thread secrets come only from separate backend credential
   reads; no `get` returns them (#98, #106).
9. `WIFI:` payloads escape `;`, `,`, `:`, `\` and `"`; one `wifiShare()` is
   shared by guest and Wi-Fi (#99, #104).
10. Release notes use `fetchPublic`: no session, https only, 1 MB cap, not
    rate limited (#107).
11. Admins carry no email (eero sends none); seats count members, not
    pending invites (#107).
12. Health score is 100 minus 14 per warning, 30 per problem and 5 per
    unknown; `health.check` reads no `{net}/diagnostics` and runs no probes
    (#117).
13. Support report redaction keeps the last four characters; values of four
    or fewer are hidden whole (#117).
14. The save bridge allows only csv, tsv, txt, json, jsonl and log, up to
    8 MB; Save QR uses Chromium's download flow (#97).
15. QR codes are always black on white, in both themes (#97).
16. The CLI host never shows UI: crashes print one line to stderr and exit
    1; on Linux the dev launcher strips the display (#115).
17. Usage labels say "24h" or "last 24 hours", never "Today", where the data
    is a rolling 24 hours (#108, #109).
18. Per-device 7-day sparklines on profile detail are left out to keep the
    page budget (#109).

## 6. Numbers, surprises, open items, next

**Numbers.** 17 PRs, 442 to 657 tests, `pnpm check` 4.1 s. Six workers at
once; one needs-file approval (#108); no failed or blocked tasks.

**Surprises.**
- The real API differs from docs and fixtures in five places, each found by
  a read-only check: the hidden default profile (31 of 47 devices pointed at
  it), `{profile}/schedules` and `{net}/proxied_nodes` 404, `app_events`
  shape, profile usage rows keyed `profile_id`, and no member emails.
- An Electron error dialog appeared on the maintainer's desktop mid-run. The
  dev CLI launcher inherited `DISPLAY`, so any crash in the CLI host showed
  a dialog. No worker reported a crash; the source is unknown. All workers
  switched to running the CLI with the display unset, and #115 makes the CLI
  headless for good.
- The CLI table printed `guest.share`'s `qr` field (which holds the
  password) without `--reveal`. Fixed in #104; request logs and MCP were
  never affected.

**Open items (carried in the roadmap).**
- M4: `profile.get` returns today's pauses (manual pause on profile detail);
  an Unassigned detail route; Activity row actions need links eero does not
  send; guest Print card and Send; Mark all read; the eero client's 5 s
  shared `GET {net}` holds the password, so a reveal right after an
  outside change can show the old one.
- M5: Simple Setup enum (question 1); Reservations & ports "IPv6 off" state
  from `settings.get`; fake eero list has no `radio_channel_stats`, so
  `--fake` Wi-Fi shows `-` for width and channel; `--fake` cannot serve the
  release manifest; `integrations.get` and `wifi.get` share the `settings`
  poll topic.
- M6: the packaged Linux launcher must strip the display too; the
  `dist:smoke` window step fails with no display; sidebar and sign-in
  avatars use an inline `hue("orange")` (from M1.7).

**Process lessons** (proposed edits to the milestone skills):
- Worker prompt: run every CLI or Electron command with the display unset
  (now enforced by #115 on Linux; keep the rule for other hosts).
- Worker prompt: when a real capture contradicts the docs or fixtures,
  report it as an open item even if the fix is outside the task's files; the
  lead turns it into a fix task (it worked for #108 and #116).
- `milestone-plan`: list `src/cli/format.ts` (secret masking) in any story
  that adds a sensitive command.
- Lead: steering a finished worker thread restarts it; check a worker's
  state before broadcasting.
