## 1. Questions

1. **Sandbox slips: check your config folder.** Two workers launched the old
   prototype app before M1.4 fixed the user data path, so it used the real
   `~/.config/mesh-ui`.
   - M1.5 ran the old window for 1 to 2 s. That build's renderer loads the
     saved session and calls eero, so a read-only eero request may have gone
     out. No write commands existed.
   - M1.7 ran it for about 10 s in demo mode. No session read, no eero call,
     but Chromium profile files and a `mesh-ui:view:v1` last-route key may
     have been written.
   Options: (a) check the folder and the eero app's activity yourself
   (recommended), (b) ignore. Nothing waits on it. M1.4 now honours
   `--user-data-dir` / `MESH_UI_USER_DATA_DIR` on every launch, proven in #20.
2. **Answered: no network chooser at sign-in.** You asked for sign-in to go
   straight to the dashboard. It now opens the last used network, else the
   first, and you switch from the sidebar (#40). The engine's own fallback
   (selection, else first network) already matches, so no engine change is
   needed.
3. **Mockups disagree with each other** on some numbers (eero traffic shares,
   band totals on the eeros page, Lake Cabin's role and eero count). Fixtures
   follow `docs/architecture/backends.md`. Options: (a) align the mockups to
   the fixtures when M2 builds those pages (recommended), (b) change fixtures
   to one mockup now.
4. **electron-builder runs through pinned `pnpm dlx electron-builder@26.18.0`**,
   not as a devDependency, because pnpm 12 rejects electron-winstaller's build
   script without an `allowBuilds` entry in a new `pnpm-workspace.yaml`.
   Options: (a) keep `dlx` (recommended, no new config), (b) add
   `pnpm-workspace.yaml` and a devDependency.
6. **Mockup 18 is out of date.** It still shows the chooser and first-run
   frames that #40 removed. Options: (a) update the mockup to welcome, code,
   dashboard (recommended), (b) keep it as the original design.
5. **Screenshot branches.** PR screenshots, including the ones in this report,
   live on eight `assets/M1.*-screenshots` branches. Options: (a) keep them
   (recommended, or the images break), (b) delete after merge.

## 5. Decisions made

Each is reversible; refer to it by number.

1. zod 4 with built-in `z.toJSONSchema`, not zod-to-json-schema (#18).
2. Backend areas use singular names matching the files; no `activity` area (#18, docs #26).
3. Command params are strict: unknown keys are `bad_params` (#18).
4. Core fills derived fields (`selected`, `planMbps`, `rating`, `nextChange`, summaries, shares) for both backends (#18).
5. The token lives only in `EeroClient`; fake origins must be loopback http (#22).
6. Queries retry at most twice; writes never retry except the one replay after a refresh (#22).
7. Demo starts signed in; scenarios switch with `demo.scenario.set` (#23, #32).
8. The CLI keeps the same user data dir as the app so it shares the session; an explicit dir always wins (#20).
9. MCP tool results that are not objects are wrapped as `{ result }` (#19).
10. Speed rating is `great` at 75% of plan, else `below_plan`; no "poor" tier (#28).
11. `device.list` gained a `status` param; its summary always covers the whole network (#29).
12. Usage windows use the network time zone; core recomputes totals (#30).
13. Sign-in opens the last used network, else the first, with no chooser or first-run screen; no network query runs before `network.select` resolves (#40, replacing #32's chooser).
14. A deliberate sign-out shows the plain Welcome; only expiry shows "Your session ended" (#34).
15. `network.get` counts.devices follows `device.list` rules, at the cost of two extra eero requests per network poll (#38).
16. CI smoke runs on PRs to `main` and `milestone/**`, one job per OS (#31).
17. Squash merges for every story PR.
18. `app.info` reports `fakeServer` (true only for an injected loopback origin) so the UI can show the fake-server code hint (#40).
19. The country list is themed with a token rule on `select option`, not a ported custom select (#40).

## 6. Numbers, surprises, open items, next

**Numbers.** 22 PRs, 331 tests, `pnpm check` 3.9 s, CI smoke 31 to 63 s per OS.

**Surprises.**
- Workers could not start the outside (Sol) review from their sessions
  (`parent_not_active`); 19 of 21 PRs were self-reviewed and say so. Only #26
  and #38 got an outside review.
- Workers whose CI wait ran in the background were ended mid-wait; M1.14
  needed four resumes. Fixed by waiting in the foreground.
- Workers shared one scratch folder; two PR bodies were briefly overwritten.
  Later prompts used unique names.
- macOS smoke failed once with a vitest `write EPIPE` after all tests passed;
  a rerun passed.

**Open items (not blocking).**
- Not built in M1: audit log; two-process session re-read on 401; cache keeps
  every network instead of the last two; burst cooldown and settle delay;
  demo latency; guest usage on the eero backend; `events.summary`,
  `usage.quiet_hours`, grouped events.
- Demo has no slow or failing scenario, so loading and error states were shown
  in `dev:fake` only.
- Devices: no counts in the eero, profile and manufacturer dropdowns; bridge,
  no-permission and missing-capability states wait on later fields.
- Sign-in: "Try demo mode" only hints a restart; "delete my account" needs a
  later command. The no-networks and load-error screens from #40 were only
  typechecked, not driven in the window. Two code comments still mention the
  old chooser (`App.tsx` header, `src/core/commands/network.ts` line 7).
- Small UI nits: bar hover ignores the column gap; gallery's third gauge wraps.
- Doc drift: `overview.md` (heatmap scaling, "Paused 25 min ago"),
  `sign-in.md` (switch, usage meter), `data-model.md` (counts from
  `clients.count`), `commands.md` (`network.select` result, `network.get`
  device count), `design-system.md` (gallery), `testing.md` (`pnpm test:ui`
  does not exist).
- safeStorage sync API deprecation warning; deb and rpm need an author email
  (M6).
