# Application

This copy of Mesh UI: the app version and updates, startup and tray, keyboard shortcuts, the application theme, and the CLI and MCP hookup. The eero account (profile, notifications, networks, sign out and deletion) is on the [Account](account.md) page.

The page was titled Settings until 2026-11-22; it sits in the sidebar's Settings group, so it was renamed Application ([#376](https://github.com/pkkid/mesh-ui/issues/376)). The route id and path stay `settings` and `/settings`, and the palette still finds it by "settings" and "preferences" (`keywords` in `routes.ts`).

Mockup: [../../mockups/17-account-settings.html](../../mockups/17-account-settings.html) (drawn before the split and the rename; this page has its CLI, theme and About sections; About is now the hero)

Shared patterns (flat hero, sections, footnotes) are described in [../overview.md](../overview.md).

## Layout

Breadcrumb `Application`, nothing after it. The last item in the sidebar Settings group; also opens from the palette, its shortcut (`Ctrl+,` by default) and deep links. One full-width column, sections `gap-14` apart; no side panel (the About panel became the hero on 2026-11-21).

1. **Hero** (the flat page header): this copy of Mesh UI, front and centre.
   - Icon: the app icon (`AppIcon`, 64px). Title: `Mesh UI 0.6.0`.
   - Status line: the update status, then on its own line under it, in the same colour but not bold, "Mesh UI is an independent app and is not made by eero or Amazon." (it was a footnote at the foot of the page until 2026-11-21). The update status (status dot and line: "Up to date · checked 20m ago", "Not checked yet", "Automatic updates off", "Checking for updates", "Version 0.6.1 is available", "Downloading 0.6.1 · 42%", "Version 0.6.1 is ready", the error line, or for deb, rpm, portable and dev installs why it does not update itself: "Installed with a package manager. Update with apt or dnf.", "Development build. Updates are off.").
   - Under the status, one stacked list in one format, every line its icon then the words: **Electron 45.3.1** (atom icon), **Platform Linux x64** (monitor icon), then the links **Release notes** and **Source and issues** (open in the browser). Label and value are one colour, one space apart (no colon); no left and right aligned columns.
   - Actions (outline, dim icons), only where this copy updates itself: **Restart to update** when an update is ready; **Download from GitHub** (an unsigned macOS build, which cannot install updates itself, with a note saying so) when one is available; **Check for updates** otherwise (spinning icon while it checks). A progress bar shows while downloading. The **Automatic updates** and **Beta updates** switches are in Application settings, below.
   - Right-hand column, **eero details** (a section-style title, `text-base font-semibold`), in the same format: **Support ID K4M9QZ** (ID card icon, mono, with a copy icon after it), then **eero support articles** (opens in the browser) and **Show eero request log** (`app.log.show`, hidden in demo mode).
2. **Application settings**, laid out like the Advanced networking groups: one card of settings rows (title, muted description, switch on the right; `Group` and `Row`). Subtitle from the settings: "Opens only when you start it. Closing the window quits it. Updates automatically." ("Opens at login", "Starts in the tray at login"; "Closing the window keeps it running in the tray."; "Updates automatically, betas included.", "Updates only when you check.", and no update sentence where this copy does not update itself). Rows:
   - **Keep running in the tray** (`app.settings.set {runInTray}`, off by default). "Closing the window keeps Mesh UI running in the system tray (the menu bar on macOS), so desktop alerts keep arriving. Quit from the tray icon." On a Linux desktop with no tray (plain GNOME) the description says so (add the AppIndicator extension) and the switch can only be turned off.
   - **Start at login** (`app.startup.set`), read back from the OS (`app.info.startup`), so a change made in system settings shows here too. Its description says what a login launch does with the tray setting as it is now: with Keep running in the tray on, "Start Mesh UI hidden in the tray when you sign in to this computer. Desktop alerts arrive without the window opening."; with it off, "Open the Mesh UI window when you sign in to this computer. Turn on Keep running in the tray to start hidden in the tray instead." A development build cannot register a login item: the switch is disabled and the description says so.
   - **Automatic updates** (`app.settings.set {autoUpdate}`, on by default). "Check for new versions at launch and every 6 hours, and download them in the background."
   - **Beta updates** (`app.settings.set {updateChannel}`). "Also get pre-releases, to try new features before they are released."
   - **Download and upload colors**, last, a menu instead of a switch: **Blue and purple** (the default, download blue and upload purple) or **Green and red** (download green, upload red). "The colors for download and upload in every chart, legend and rate. Saved on this computer." View state in localStorage like the theme (`lib/trafficColors.ts`), no command; both choices take the active theme's hues.
   Where this copy does not update itself (deb, rpm, portable, dev) both update switches show off and disabled, and Automatic updates' description says "This copy of Mesh UI does not update itself. Get new versions from the release page or your package manager."
   Keep running in the tray comes first, because what Start at login does depends on it. Each switch writes at once with a toast and Undo. See [cross-platform.md#system-tray](../../platform/cross-platform.md#system-tray) and [#start-at-login](../../platform/cross-platform.md#start-at-login).
3. **Keyboard shortcuts**, subtitle "Saved on this computer.", laid out as T3 Code's keybindings settings. Two cards of three rows side by side (`md:grid-cols-2`, `gap-4`; stacked when narrow), one row per rebindable action. Left: Open command palette (`F1`), Toggle DevTools panel (`F12`), Open application settings (`Ctrl+,`, `⌘,` on macOS). Right: Refresh page data (`F5`), Go back (`Alt ←`, `⌘[` on macOS), Go forward (`Alt →`, `⌘]`). On the right each row shows its one key combination as separate key caps (`Kbd`, no `+` between them), or a muted "Unassigned" once removed, in a borderless pill that looks like a button on hover (`hover:bg-accent`, a faint border). Clicking the pill turns it into a 176px mono field with the placeholder "Press shortcut"; the next combination is saved at once and the pill comes back. `Esc`, `Tab` or clicking away cancels. A refused combination stays in the field (marked invalid) with the reason under the row in warning colour ("F1 is already used by Open command palette.", "Ctrl+C is kept for Copy.", "Add Ctrl or Alt, so typing in a field isn't taken over. F-keys work alone."), and the field keeps recording. Left of the pill, a ghost `⋯` button, shown while the row is hovered or focused (always on touch), opens a menu: **Reset to default** (once the keys differ from the default) and **Remove** (destructive colour, while the action has keys). Header tool **Reset all** (ghost) when any action is changed. Fixed shortcuts (`Ctrl+1` to `7`, `Ctrl+Shift+N`, `[` `]`, `/`, ...) are not listed. Rules and the full list: [overview.md#keyboard-shortcuts](../overview.md#keyboard-shortcuts).
4. **Application theme**, subtitle from the picked themes (`Dark mode, Classic`; `System mode, Grove light and Ocean dark`), as in T3 Code. Header tool **Add theme** opens a wide sheet: a search of Open VSX color themes (search box, a Most popular / Top rated / Newest dropdown, a list that fades at its scrolled edges: the extension's icon, its name, `publisher · 1.1M downloads`, then the description in at most two lines, all muted text one size, each with **Install** (package icon); main fetches the icons and passes them as data URLs, so the renderer stays offline), then "or import a file" to choose, drop or paste VS Code (or Mesh UI / T3 Code) theme files, with **Add theme** in the footer. Adding switches light and dark to the new theme's first light and dark styles. First a row of three tiles, System, Light and Dark, each as wide as one theme card column and centered above the cards (measured from the cards' grid, so they never stretch across the full-width section), each a small wireframe of the window in the picked themes (System splits light and dark down the middle). Then one card per theme or collection (Classic, Rose, Grove, Ocean, Ember, Iris, then added themes), each with a light and a dark preview circle. A circle sets the theme for that mode only; the card's name sets both. The circles in use have a ring and a sun or moon badge. A collection (an added Gruvbox: Hard, Medium, Soft) labels each circle with the picked style and "+2"; hovering a circle fans out the other styles. Each card has a "..." menu after its name (the row menu used on tables): Duplicate (every theme), Edit (added themes), Export (every theme; a collection exports as one file) and Remove (added themes, in red). On a collection, Duplicate and Edit name the style they act on ("Duplicate Hard"). Duplicate and Edit open the floating theme editor in the bottom right of the window: name, Light / Dark palette, Simple (background and accent) or Advanced colors by area, chart colors, a live preview on the page behind it, a spotlight of where a color is used and Inspect to pick a color from the page. The header holds the title with a status line under it that keeps its height when empty (the selected color and its uses, or the Inspect hint), and Inspect (outline), minimize and close at the top. Rows fade under the header and footer as they scroll; a selected color row is highlighted by fill only. The footer is the sheets' band: Cancel and **Save theme** (**Create theme** for a duplicate). A deep drop shadow (T3 Code's theme editor shadow) stands in for a backdrop, since the panel leaves the page usable. See [design-system.md#themes](../../design/design-system.md#themes). Footnote: pick a light and a dark look; themes are stored on this computer only.
5. **Command line and agents**, subtitle `38 commands this week, MCP used 5m ago` (`No commands this week`, `MCP not used yet`) from the audit log; Mesh UI cannot see whether an agent is connected right now, only when one last ran a command. One card of settings rows. First **Command line** ("The mesh-ui command in a terminal or script.") and **MCP server** ("AI agents connected with mesh-ui mcp."), each with a menu: **Off**, **Read only**, **Changes**, **Full access** (`app.access.set`; defaults Full access for the command line, Changes for MCP). The description adds what the chosen level allows: Off "Every command is refused."; Read only "Can look at the network, but not change it."; Changes "Can look and make changes, such as pausing a device or restarting an eero, but never delete or hand over anything."; Full access "Can run every command, including ones that cannot be undone, such as removing an eero." Then **Reveal secrets**, one switch for both (`app.access.set {secrets}`, off by default): "When off, the command line and AI agents can never see the Wi-Fi password, the guest Wi-Fi password or the Thread credentials, whatever their access level. This window can always show them." See [security.md](../../architecture/security.md#access-levels). The last, taller row holds the hookup and this week. A surface set to Off shows no hookup: no **Run a command** block when the command line is off, no **Add MCP server** blocks when MCP is off, and with both off no left side (nor Install CLI), only This week across the row. Left: **Run a command** code block (`mesh-ui run device.list`) and **Add MCP server** code blocks, one per agent CLI (`claude mcp add mesh-ui -- mesh-ui mcp`, `codex mcp add mesh-ui -- mesh-ui mcp`, `agy mcp add mesh-ui mesh-ui mcp` for Antigravity), each with a copy icon. When this copy can put `mesh-ui` on PATH itself (`cli.canInstall`: macOS, or the AppImage) and has not, or the link points at a copy that moved, the left side is instead "Use Mesh UI from a terminal" with **Install CLI** (or **Reinstall**) and, under "Or add it to PATH yourself", the `export PATH=...` line to copy (on macOS this is what to use after declining the admin prompt). When the launcher is installed but its folder is not on PATH (AppImage without `~/.local/bin` on PATH, the Windows portable zip), a "Not on PATH yet" note with that line follows the code blocks. Right: "This week" and "38 commands from the CLI and agents" ("No commands yet"), a sparkline of the 7 days, and the latest 100 commands this week in a list that scrolls past about eight rows (`app.audit.list {limit: 100}`) (`CLI` or `MCP` for where it ran, id in mono, `needs confirm` or `blocked` (refused by the access level) in warning colour when it was refused, age). Empty: "Commands run with mesh-ui or by an AI agent show here." Footnote: everything in this window is also a command; agents never see the session token or change their own access, and restarting or irreversible commands only run with `--confirm`.

the page scrolled to it (a second `settings` route, `/settings/:section`,
listed after the other `/settings/*` pages so they match first, and its

The sidebar's update chip opens `#/settings/about`. Links saved before the

## Data

| Element | Command | Refresh |
| --- | --- | --- |
| CLI install state, MCP state, command log and counts | `app.info`, `app.audit.list` | on load, every 60 s |
| Themes | renderer local storage (not a command) | |
| Keyboard shortcuts | renderer local storage `mesh-ui:shortcuts`, overrides over the defaults (not a command) | |
| Version, update status, Electron, platform | `app.info` | on load, every 60 s, and on `update.changed` |
| Automatic updates, Beta updates, Keep running in the tray switches | `app.settings.get` | on load, after writes |
| Start at login, whether this desktop has a tray | `app.info` (`startup`, `tray`) | on load, every 60 s, after writes |

## Actions

| Control | Command | Effect | Confirm | Result |
| --- | --- | --- | --- | --- |
| Copy CLI or MCP line | none | | | Copies the text |
| Command line or MCP server access menu | `app.access.set` | write (app local) | | Saved in `settings.json`; the engine applies it to the next CLI or MCP call |
| Reveal secrets switch | `app.access.set {secrets}` | write (app local) | | Saved in `settings.json`; Undo in the toast |
| Install CLI (shown when the launcher is missing) | `app.cli.install` | write (app local) | OS admin prompt where needed | `mesh-ui` on PATH |
| Theme orb | none (view state) | | | Applies the theme; stored in local storage |
| Shortcut pill, Reset to default, Remove, Reset all (Keyboard shortcuts) | none (view state) | | | Rebinds the action at once; stored in local storage |
| Check for updates | `app.update.check` | write (app local) | no | Checks GitHub Releases now, even with automatic updates off |
| Download from GitHub (unsigned macOS, state `available`) | none | | | Opens the release page in the browser |
| Restart to update (hero; the sidebar chip opens `#/settings/about`, the hero) | `app.update.install` | write (app local) | no | Mesh UI restarts into the new version; only on this click |
| Automatic updates switch | `app.settings.set` `{autoUpdate}` | write (app local) | no | Scheduled checks stop or resume |
| Beta updates switch | `app.settings.set` `{updateChannel}` | write (app local) | no | `beta` also takes GitHub pre-releases |
| Start at login switch | `app.startup.set` `{enabled}` | write (app local) | no | Adds or removes the OS login item; toast with Undo |
| Keep running in the tray switch | `app.settings.set` `{runInTray}` | write (app local) | no | The tray icon appears or goes at once; with it on, closing the window hides it to the tray; toast with Undo |
| Hero links (Release notes, eero support articles, Source and issues) | none | | | Open externally |
| Show eero request log (hero) | `app.log.show` | write (app local) | no | The file manager opens on `eero-requests.jsonl` |

## States

- **CLI not installed:** the code blocks show **Install CLI** instead of copy (AppImage and macOS); on deb, rpm and Windows installs the launcher is already on PATH.
- **MCP not connected:** the subtitle ends "MCP not used yet".
- **No commands this week:** "No commands from the CLI or agents this week."

## Notes

- The command log (`app.audit.list`) reads the audit log the engine writes on every CLI and MCP call, `audit.jsonl` in the config dir. Format, redaction and the 1,000 line cap are in [security.md](../../architecture/security.md#audit-log); it never holds the token or secret params. Window initiated commands are not logged.
- The section subtitle ends "MCP used <age>" (or "MCP not used yet"), from the latest MCP call in the audit log; there is no persistent connection to detect, so it never says "connected" (decided in M6.6).
- Theme and panel state are renderer preferences in local storage, not commands; settings the CLI also needs live in `settings.json`.
- Commands added: `app.audit.list` q, `app.access.set` w.
